STYLOTEKA 5.3.20 — вартість події + посилання на банку monobank

ОСНОВНЕ
- У формі створення/редагування події вже можна вибрати «Безкоштовно» або «Платна подія».
- Для платної події з ручним підтвердженням додано окреме поле «Посилання на банку monobank».
  Приклад формату: https://send.monobank.ua/jar/XXXXXXXX
- Зберігається точна сума в гривнях і посилання на банку. За потреби можна додати
  текстові інструкції, але посилання й інструкції не можна залишити порожніми одночасно.
- Учасник натискає «Я йду», бачить суму та кнопку «Оплатити через банку monobank»;
  після переказу завантажує квитанцію (JPG/PNG/WEBP/PDF до 5 МБ).
- Банка НЕ фіксує автоматично сплату саме вартості квитка і НЕ підтверджує участь.
  Організатор звіряє суму й одержувача за квитанцією та натискає «Підтвердити».
- Лише після підтвердження заявка з’явиться у списку «Йдуть» і бот надішле
  адресу та перелік настільних ігор особисто підтвердженому учаснику.
- Для безкоштовних подій нічого не змінюється.
- Збережено сумісність зі старими подіями, ручними реквізитами і, якщо була
  налаштована, автоматичною оплатою monobank acquiring.
- Сервер приймає лише HTTPS-посилання на домен send.monobank.ua з шляхом /jar/…

ЯК ОНОВИТИ
1. Зробіть резервну копію GitHub-репозиторію та бази Supabase.
2. Якщо попередня міграція EVENT_RECEIPTS_SETUP.sql з версії 5.3.19
   ВЖЕ застосована, виконайте у Supabase SQL Editor тільки:
       EVENT_MONOBANK_JAR_UPGRADE_v5_3_20.sql
   Якщо v5.3.19 ще НЕ встановлена, спочатку виконайте:
       EVENT_RECEIPTS_SETUP.sql
   із цього архіву. У ньому вже є нове поле payment_link і логіка квитанцій.
   НЕ запускайте обидва файли як обов'язкові окремі міграції.
3. Замініть у GitHub ТІЛЬКИ файли app.py та index.html з цього архіву.
   Не видаляйте інші файли, шрифти, картинки та налаштування Render.
4. Після успішного деплою Render закрийте й відкрийте Telegram Mini App.
5. Перевірте платну подію в тестовому сценарії:
   створення → зазначення ціни → вставка банки → анонс у Telegram →
   «Я йду» → відкриття банки → квитанція → підтвердження адміном →
   особисте повідомлення з адресою та іграми.

БЕЗПЕКА І ЗРУЧНІСТЬ
- Зовнішня банка не є підтвердженням платежу. Учасник має явно вказати суму.
- Після появи квитанцій для події змінювати банку заборонено, щоб не плутати
  перекази різних людей.
- Посилання на банку та реквізити не повертаються в публічному списку подій:
  учасник бачить їх після входу через Telegram у вікні оплати.
- Платіжні квитанції мають залишатися в приватному bucket event-receipts.
- Telegram дозволяє надсилати людині особисті повідомлення від бота лише після
  натискання Start у приватному чаті з ботом.

ПЕРЕВІРКИ
- 20 локальних тестів безпеки/логіки пройдено.
- Python синтаксично перевірений, inline JavaScript пройшов node --check.
- Реальне платежне зарахування та приватні Telegram-повідомлення треба
  перевірити після деплою з реальними акаунтами (не робіть тестових переказів,
  доки не перевірите правильність банки та її одержувача).
