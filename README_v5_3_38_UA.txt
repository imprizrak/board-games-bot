STYLOTEKA 5.3.38 — КЛІКАБЕЛЬНІ ПОСИЛАННЯ У ПОДІЯХ

ЗМІНИ
- URL у публічному описі події більше не показується довгим текстом.
- Кожне http(s) посилання відображається як короткий підсвічений елемент «Посилання ↗».
- Натискання всередині Telegram використовує Telegram WebApp.openLink; звичайний браузер відкриває посилання у новій вкладці.
- Підтримуються https://, http://, www., t.me/..., instagram.com/... та facebook.com/...
- Знаки пунктуації після URL не включаються у посилання.
- Оригінальна адреса зберігається в описі й залишається доступною для редагування.
- Той самий вигляд посилань діє у приватному перегляді заявки адміністрацією.
- Текст опису екранується від HTML-ін'єкцій, дозволені лише звичайні http(s) посилання.

ВСТАНОВЛЕННЯ
- Якщо в GitHub уже є Styloteka 5.3.37, замініть ЛИШЕ index.html із цього архіву.
- Якщо 5.3.37 ще не встановлена, оновіть app.py разом з index.html; SQL для заявок 5.3.37 уже був застосований у Supabase на попередньому кроці.
- Коміт у GitHub запустить звичайний автодеплой Render за наявного налаштування.
- Додаткових SQL-міграцій саме для 5.3.38 немає.
- Цей архів не завантажено до GitHub та не розгорнуто на Render автоматично.

ПЕРЕВІРКА
- Браузер: 320 / 375 / 393 / 430 px, перевірено клікабельні лінки та Telegram.openLink.
- HTML-ін'єкція не виконується; URL перевіряються й екрануються.
- Регресійні тести заявок і адміністрування пройшли (4 ширини).
- Регресійні тести iPhone-віджетів пройшли (5 ширин).
- Реальне відкриття зовнішнього сайту в Telegram iOS слід перевірити після деплою.
