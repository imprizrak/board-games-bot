STYLOTEKA 5.3.41 — ЧАС НАТИСКАННЯ «Я ЙДУ» У ПІДТВЕРДЖЕННІ ОПЛАТИ
===============================================================

ЩО ЗМІНИЛОСЯ
1) При натисканні «Я йду — квитанція» сервер записує час ПЕРШОГО натискання
   за підтвердженим Telegram ID та ID події. Час береться із Supabase, а не з телефону.
2) Адмін у «Перевірка оплат» бачить:
   — коли учасник уперше натиснув «Я йду»;
   — коли вперше надіслав квитанцію (наявне created_at);
   — коли адміністрація прийняла рішення (наявне reviewed_at).
   Ці дані повторюються у діалозі підтвердження оплати.
3) Час показується за Europe/Kyiv, із датою і годинами/хвилинами.
4) Для старих записів, де натискання ще не зберігали, показується
   «Не зафіксовано»; дата квитанції не підміняє дату натискання.
5) Якщо журнал натискань тимчасово недоступний, адміністратор усе одно
   може переглядати/підтверджувати квитанції; не ламаємо чинний платіжний процес.

ВСТАНОВЛЕННЯ
1) Скопіювати app.py та index.html з архіву до кореня GitHub-репозиторію
   imprizrak/board-games-bot (гілка main), замінивши обидва попередні файли.
2) Render із auto-deploy має запустити нове розгортання після коміту.
3) SQL «styloteka_first_event_join_click_times.sql» уже застосований до
   продакшн Supabase 22.11.2026; вдруге застосовувати не потрібно.
4) У Telegram відкрити платну подію з оплатою через банку → натиснути
   «Я йду» → надіслати квитанцію → відкрити адмінський розділ
   «Перевірка оплат». Першу позначку часу має бути видно там і в підтвердженні.

ВАЖЛИВО
— Зміна НЕ опублікована в GitHub або Render цим ZIP.
— Працює для подій зі способом оплати «квитанція/банка» (payment_method=receipt).
  Монобанк-еквайринг підтверджується автоматично і не має цієї адмінської форми.
— Історичні натискання до розгортання не можна відновити заднім числом.
— Списки квитанцій і час натискань доступні лише серверу та авторизованим адмінам.
— «Квитанцію вперше надіслано» — timestamp першого завантаження, навіть якщо
  квитанцію після відхилення замінили новою.
