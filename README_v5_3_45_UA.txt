STYLOTEKA 5.3.45 — АВТОЗАПОВНЕННЯ НОВИХ І НАЯВНИХ ІГОР
=========================================================

ЩО ДОДАНО
- У формі «Додати настільну гру»: «✨ Знайти гру та автозаповнити».
- У вже доданій грі: відкрити гру -> «Редагувати» -> «✨ Автозаповнити наявну гру».
- Пошук збігів на BoardGameGeek, вибір конкретного видання, перегляд характеристик.
- Окремі пропозиції відео YouTube і правил із результатів вебпошуку.
- Для існуючих ігор можна відмітити ЛИШЕ потрібні поля: назву, опис,
  характеристики, посилання на правила, відео, обкладинку.
- Заповнені поля за замовчуванням НЕ позначені для перезапису.
- Всі перенесені дані спочатку потрапляють до форми; зміни зберігаються
  лише після окремого натискання «Зберегти зміни».
- Під час заміни обкладинки чи PDF сервер зберігає старий файл, доки
  новий файл і оновлення запису успішно не завершаться.
- Адмін-доступ для редагування наявних ігор не змінено.

ВАЖЛИВО ПРО ДЖЕРЕЛА
BoardGameGeek з 2025 року вимагає схвалену реєстрацію застосунку та Bearer-токен:
https://boardgamegeek.com/using_the_xml_api
https://boardgamegeek.com/applications
У Render -> Environment додати:
  BGG_API_TOKEN         — ОБОВ'ЯЗКОВИЙ для автоматичного заповнення характеристик.
  YOUTUBE_API_KEY       — необов'язково, для вибору справжніх відеооглядів.
  BRAVE_SEARCH_API_KEY  — необов'язково, для пошуку посилань на правила.
Жоден ключ не можна додавати в index.html чи зберігати в GitHub.
Без ключів користувач може додавати і редагувати ігри вручну;
форма також пропонує посилання на звичайний пошук, але НЕ вигадує дані.
Перевір відповідність правил та відео конкретному виданню гри.

ВСТАНОВЛЕННЯ
1. Зроби резервну копію репозиторію.
2. У корінь репозиторію GitHub заміни/додай ВСІ ТРИ файли:
     app.py
     index.html
     game_autofill.py  <-- НОВИЙ, обов'язковий файл; без нього імпорт app.py зламається.
3. Переконайся, що requests уже є у requirements.txt (він використовувався
   і раніше; нових Python-пакетів не потрібно).
4. Додай API-ключі як змінні середовища Render і запусти нове розгортання.
5. Перевір окремо нову гру та редагування вже існуючої, бажано спочатку
   на тестовій картці, не перезаписуючи робочі описи/обкладинки.

ЗМІНИ В SUPABASE
Нові таблиці та SQL-міграції не потрібні. Поточні дані в бібліотеці
не змінювалися під час підготовки цього архіву.

ПЕРЕВІРКИ
- Браузерні сценарії (320, 375, 393, 430 px): нова гра, редагування
  наявної, вибір полів, збереження лише після підтвердження.
- Провайдер: BGG XML, Bearer-заголовок, перевірка адрес обкладинок,
  коректна поведінка без токена (використано тестові відповіді).
- Регресія: стрічка подій, iPhone-віджети й вибір гравця (320–768 px).
- Живі API-ключі BGG, YouTube, Brave у цьому середовищі не підключені;
  зовнішній запит із реальними ключами та запуск на Render ще НЕ перевірені.
