STYLOTEKA 5.3.37 — ЗАЯВКИ НА ПОДІЇ ВІД УЧАСНИКІВ

ЗМІНИ
• Звичайний учасник Telegram-групи може натиснути «+» → «Запропонувати подію».
• Заявка зберігається ПРИВАТНО, має статус pending і не з’являється в подіях/публічних Telegram-повідомленнях.
• Учаснику доступна кнопка «Мої заявки»: статуси «Очікує», «Схвалено», «Відхилено».
• Адміністратору доступна кнопка «На розгляді» з переглядом приватних деталей, редагуванням та схваленням/відхиленням.
• Після схвалення створюється нова подія в events і надсилається звичайний анонс у гілку «Анонси подій».
• Повторне схвалення не створює дубліката. Платні пропозиції допускають ручну перевірку квитанції; автоматичний monobank доступний тільки після рішення адміністрації.
• Бот пробує надіслати адміністраторам приватне повідомлення про заявку, але адміністратор має раніше натиснути Start в особистому чаті.

ВСТАНОВЛЕННЯ
1. SQL EVENT_SUBMISSIONS_SETUP_v5_3_37.sql уже застосований у Supabase проєкті Styloteka. Повторно запускати його не потрібно.
2. Замінити у GitHub файли app.py та index.html з цього архіву одночасно одним комітом.
3. Дочекатися успішного деплою Render. Перевірити, що в Telegram відкривається оновлений mini-app.
4. Увійти звичайним учасником групи, натиснути «+» на вкладці «Події», подати тестову заявку.
5. Адмін → Події → На розгляді → перевірити реквізити й натиснути «Схвалити».
6. Перевірити появу нової події та її повідомлення у Telegram, потім прибрати тестову подію.

ПРИМІТКИ З БЕЗПЕКИ
• Авторизація на API перевіряє підписані Telegram WebApp initData й членство у підключеній групі.
• Адмінські дії перевіряються на сервері через Telegram getChatMember. Кнопки в UI — не захист.
• Нову таблицю закрито RLS і дозволено доступ лише service_role. Не переносити Supabase service_role ключ у index.html!
• Якщо бот не має права перевіряти учасників групи, реєстрація заявки буде відхилена (fail-closed).
• Публікація нової події відбувається транзакційною SQL-функцією з блокуванням рядка (захист від дублікатів).
• Для пропозицій учасників оплата через Monobank Jar лише за квитанцією; адміністрація повинна перевіряти, чи належить банка клубу.
• Якщо в адміністратора не відкритий приватний чат із ботом, нотифікація в DM не надійде, але заявка буде у списку «На розгляді».

ПЕРЕВІРКИ
• 9 ізольованих серверних тестів.
• 4 браузерні сценарії Playwright на 320, 375, 393, 430 px.
• Живий SQL-транзакційний тест: створення, заборона повторного схвалення, повний ROLLBACK.
• На реальному Telegram WebView після деплою ще треба перевірити.

Версія 5.3.37 створена поверх клієнтської 5.3.36.
SQL додається також для інших інстансів Styloteka.
Встановлених змін у код на Render немає до оновлення GitHub.
