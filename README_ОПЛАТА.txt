STYLOTEKA v4.4 — ПЛАТНІ ПОДІЇ + MONOBANK ЕКВАЙРИНГ

У цьому архіві: index.html і app.py — повні файли на основі v4.3.

ЩО ЗМІНЕНО
• Створення/редагування події: «Вартість» → «Безкоштовно» або «Платна подія» із сумою в гривнях.
• Груповий анонс показує ціну.
• Безкоштовна подія: старий запис «Я йду», без оплати.
• Платна подія: «Я йду · ХХ грн» у Telegram-групі відкриває Telegram Mini App, а він відкриває індивідуальний рахунок monobank.
• Лише підтверджений API банку статус success створює RSVP зі статусом going (або waitlist, якщо стан події було змінено вручну).
• Несплачені рахунки не створюють записів учасників.
• Резервування місць на час платежу — у транзакційній функції Supabase; після завершення/прострочення рахунку місце знову стає доступним.
• Повторне натискання не має створювати другий активний рахунок користувача.
• Вебхук + резервна перевірка статусу; повторні вебхуки ідемпотентні.
• Захист від видалення події з історією оплат і від небезпечного зменшення ліміту місць.
• Всі інші функції v4.3 збережено: рамки, розширені анонси, ігри учасників та профілі.

ВСТАНОВЛЕННЯ
1. Розпакуйте архів і замініть обидва файли в корені GitHub-репозиторію:
   index.html, app.py. Дочекайтеся успішного деплою Render.
2. У Render → board-games-bot → Environment додайте секретну змінну
   MONOBANK_ACQUIRING_TOKEN = токен мерчант-еквайрингу monobank.
   За потреби можна задати MONOBANK_PUBLIC_URL=https://board-games-bot-hkfp.onrender.com
   Токен НЕ записуйте в код, GitHub, повідомлення бота чи чат.
   Отримання: кабінет мерчанта https://web.monobank.ua/
   Особистий токен банкінгу або посилання на «банку» НЕ замінює токен еквайрингу.
3. Для групових кнопок має працювати Main Mini App у @BotFather або
   встановлений TELEGRAM_APP_SHORT_NAME для іменованої Mini App.
4. Вебхук буде налаштований при створенні рахунку на адресу
   https://board-games-bot-hkfp.onrender.com/api/payments/monobank/webhook
   (береться з WEBAPP_URL, якщо її вказано, або з адреси HTTPS сервісу).
5. У Supabase вже застосовано необхідні міграції: events.price_kop,
   event_monobank_payments, два серверні RPC; повторно запускати SQL не потрібно.

ПЕРЕВІРКА ПЕРЕД РЕАЛЬНИМИ ПРОДАЖАМИ
• Створіть безкоштовну подію і перевірте безкоштовний запис.
• Створіть тестову платну подію з невеликою сумою та перевірте шлях «група → Telegram Mini App → monobank».
• Перевірте, що без платежу учасника немає, а після підтвердження від банку він з’являється.
• Перевірте повторний вебхук, відмову/прострочення, заповнений захід та повернення у Mini App.
• Перевірте, що після появи рахунків подію неможливо видалити без ручного врегулювання оплат.
• За потреби повернення грошей і питання фіскалізації врегульовуються у вашому мерчант-кабінеті monobank.

УВАГА
Це підготовлена інтеграція, а не проведена реальна оплата: без токена еквайрингу
кнопка не зможе сформувати рахунок. Ми не проводили тестову транзакцію за гроші.
Інтерфейс і Python перевірені статично, підтвердження платежу відтворено з мок-даними.
