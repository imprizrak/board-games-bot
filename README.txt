STYLOTEKA v4.8 — ОХАЙНІ ПОДІЇ В TELEGRAM-ГРУПІ

ВСТАНОВЛЕННЯ
1. Розпакуйте ZIP.
2. Замініть ТІЛЬКИ app.py у корені GitHub-репозиторію imprizrak/board-games-bot.
3. index.html, sw.js, offline.html, Supabase і змінні середовища Render НЕ змінюйте.
4. Дочекайтеся нового деплою Render зі статусом live.
5. Створіть НОВУ тестову подію з фото та коротким описом і перевірте її пост у групі.
6. Потім перевірте подію з довгим описом і натискання «Я йду».

ЩО ЗМІНИЛОСЯ
- Для звичайної короткої події фото, назва, дата, час, вартість, інші відомості та кнопки розташовані в ОДНОМУ пості (Telegram sendPhoto + caption + reply_markup).
- Якщо опис не вміщується у підпис Telegram (1024 символи), під фото залишається головна інформація й кнопки, а весь опис іде продовженням окремими повідомленнями-відповідями.
- Величезний Google Maps URL не друкується в тексті місця: він доступний через кнопку «📍 Маршрут». Якщо можливо, відображається людська назва адреси/місця.
- Нагадування за добу використовують той самий формат.
- Після «Я йду» лічильник на фото оновлюється без зникнення продовження; нагадування зберігають заголовок.
- Якщо Telegram відхилить фото, бот відправить текстовий пост з усіма даними та кнопками.
- Платні події продовжують використовувати existing Telegram Mini App/monobank payment flow; backend платежів не змінений.

ВАЖЛИВО
- Telegram технічно обмежує підпис під фото 1024 одиницями тексту, звичайне повідомлення — 4096. Довгі описи розбиваються на частини без обрізання змісту.
- РАНІШЕ опубліковані пости автоматично НЕ переписуються. Виправлення діє для НОВИХ анонсів і нагадувань після деплою.
- Для цього оновлення не потрібні нові міграції Supabase чи токени.
- Перевірені Python py_compile і сценарії з симульованими відповідями Telegram API; реальний пост після деплою потребує перевірки в групі.
