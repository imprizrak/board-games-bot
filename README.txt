Styloteka v5.0 — зв'язок подій із Quests Inc (перший робочий етап)
=================================================================

ВСТАНОВЛЕННЯ
1. У GitHub imprizrak/board-games-bot заміни тільки app.py та index.html.
2. Дочекайся успішного деплою Render. Таблицю event_group_posts та поля в events у Supabase уже створено.
3. У Styloteka відкрий «Події» → створи або відредагуй захід.
4. Встав URL ТІЄЇ САМОЇ події Quests Inc (https://share.quests.inc/...).
5. У полі «Скільки людей іде через Quests Inc» введи актуальну цифру.
6. Збережи подію. Styloteka покаже окремо власні записи, Quests та загальну кількість записів.

ГРУПОВІ ПОВІДОМЛЕННЯ
- Для НОВИХ постів і нагадувань бот зберігає ID повідомлення й редагує текст/підпис після нових RSVP,
  підтверджених банком оплат або оновлення полів події, замість публікувати новий пост.
- Кнопка «🔗 Учасники Quests Inc» веде на сторінку пов'язаної події.
- Для СТАРОГО групового поста: адміністратор відповідає на саме повідомлення бота текстом
  /bindevent 123
  де 123 — ID події в Styloteka. Це дає змогу надалі оновлювати лічильники в старому пості.
- Під час редагування кількості Quests пост оновлюється, але нових push у групу не надходить.

ОБМЕЖЕННЯ
- Автоматичної синхронізації Quests Inc та імпорту окремих профілів НЕМАЄ: Quests API не підтверджений.
  Потрібне реальне публічне посилання на Quests-захід для перевірки технічних можливостей.
- Кількість Quests задає тільки адмін; це не підтверджені автоматично дані.
- «Разом» означає кількість ЗАПИСІВ, а не гарантовано унікальних людей: одна людина може
  зареєструватися в обох застосунках. Автоматичного дедуплікування немає.
- Обмеження місць і підтвердження платежів у Styloteka залишаються незалежними від Quests;
  не слід продавати місця понад місткість, орієнтуючись лише на сумарний індикатор.
- Профілі Quests відкриваються лише через дозволений сервісом зовнішній URL, не імпортуються до бота.
- Оновлення тексту вже опублікованого поста не створює стандартного push у Telegram.
