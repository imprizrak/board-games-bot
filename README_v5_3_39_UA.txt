Styloteka 5.3.39 — виправлення завантаження квитанцій (Android PDF)

Що встановити:
1. У репозиторії GitHub imprizrak/board-games-bot замінити ОБИДВА файли app.py та index.html файлами з архіву.
2. Дочекатися успішного автоматичного розгортання Render.
3. Закрити Telegram Mini App повністю, знову відкрити подію та надіслати квитанцію.

Що виправлено:
- PDF із службовим префіксом/маркером BOM, коли %PDF- не стоїть у першому байті, тепер розпізнається за стандартним заголовком у перших 1024 байтах.
- Тип файлу визначається за вмістом, а не за назвою: JPG, PNG, WEBP і PDF (до 5 МБ).
- При невалідному файлі замість загального «Не вдалося надіслати» користувач отримує чітку інструкцію зберегти дійсний PDF або відправити JPG/PNG скриншот.
- Додано повідомлення для порожніх файлів, перевищення 5 МБ, відсутньої авторизації та збою сховища.
- Логування небезпечного/невідомого формату містить лише MIME, кількість байтів та коротку сигнатуру, без вмісту квитанції чи особистих даних.

Результати діагностики до виправлення:
У Render 2026-11-21 близько 16:53 UTC POST /api/events/21/receipt для Android повертав HTTP 400 із відповіддю 35 байтів, що відповідає receipt_invalid_format.
Інші запити завантаження квитанцій повертали 201. Supabase bucket event-receipts приватний, дозволяє PDF/JPG/PNG/WEBP до 5 МБ.
Немає доступу до байтів відхиленої квитанції; якщо вона була пошкоджена або не містила правильного PDF-заголовка, її доведеться зберегти заново або надіслати JPG/PNG скриншот.

База даних:
Міграцій SQL не потрібно. Дані й уже відправлені квитанції збережені.

Безпека:
Лише реальні PDF та JPEG/PNG/WEBP приймаються; файл із розширенням .pdf, що фактично містить інший формат, усе одно відхиляється. Права адміністратора, перевірка Telegram і підтвердження оплат не змінені.
